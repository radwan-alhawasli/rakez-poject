# منح الماركيتنغ صلاحية عرض قائمة الموظفين (Backend)

الواجهة الأمامية تستدعي **GET /api/hr/users** في تاب **خطط الموظفين** (Marketing → خطط الموظفين) لتحميل قائمة الموظفين وفلترتها لعرض موظفي الماركيتنغ فقط. إذا كان الباكند يرد **403 Forbidden** مع رسالة "هذه الصلاحية متاحة فقط للموارد البشرية"، يجب منح دور **marketing** صلاحية **عرض فقط** (GET) لهذا المسار.

---

## الصلاحية في الواجهة الأمامية

- **مفتاح الصلاحية:** `hr.users.view`
- **الوصف:** عرض قائمة الموظفين (لخطط الموظفين واختيار الفريق).
- تم إضافتها لدور **marketing** في `src/constants/permissions.js` (BOOTSTRAP_ROLE_MAP.marketing).

---

## الـ endpoint المطلوب السماح به للماركيتنغ (قراءة فقط)

| Method | المسار | الغرض |
|--------|--------|--------|
| GET | `/api/hr/users` | قائمة الموظفين (لخطط الموظفين واختيار الموظف في الماركيتنغ) |

**ملاحظة:** لا حاجة لمنح الماركيتنغ صلاحية POST/PUT/DELETE على `/api/hr/users` — فقط GET.

---

## تنفيذ في الباكند (Laravel مثلاً)

### 1) إذا كنت تستخدم صلاحيات (permissions)

- أضف صلاحية `hr.users.view` في جدول الصلاحيات.
- امنح صلاحية `hr.users.view` لدور **marketing**.
- في الـ middleware أو الـ Controller لـ `GET /api/hr/users`:
  - اسمح بالوصول إذا كان المستخدم لديه `hr.users.create` أو `hr.employees.manage` (HR كامل) **أو** `hr.users.view` (عرض فقط، للماركيتنغ).

### 2) إذا كان الفحص بالدور فقط (role)

عدّل التحقق بحيث يسمح لـ **marketing** و **hr** (و **admin** إن كان لديه صلاحية HR) بطلب **GET** فقط لـ `/api/hr/users`:

```php
// مثال في HrUserController أو Middleware
if (request()->isMethod('GET') && in_array($user->role, ['marketing', 'hr', 'admin'])) {
    return; // allow
}
if (!in_array($user->role, ['hr', 'admin'])) {
    abort(403, 'غير مصرح - هذه الصلاحية متاحة فقط للموارد البشرية');
}
```

بعد التعديل، تاب **خطط الموظفين** في الماركيتنغ سيعرض قائمة الموظفين دون 403.
